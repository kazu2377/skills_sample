# テスト標準・テスト仕様書 作成プロンプト

## 概要

単体テスト標準、および処理方式別（バッチ/画面/API）の単体テスト仕様書を Excel 形式で作成する。不具合報告書フォーマットとエビデンス報告書も含む。

---

## 成果物1: 単体テスト標準（Excel形式）

### シート構成

#### シート1: 表紙

- PJ名、システム名、版数、作成日

#### シート2: 変更履歴

| No. | 版数 | 変更日 | 区分 | 変更箇所 | 変更内容 | 担当者 |
| --- | ---- | ------ | ---- | -------- | -------- | ------ |

#### シート3: 目次

#### シート4: 「1. 本書について」

- **1.1 本書の位置付けと目的**: 単体テストのテスト方針・観点を明確にし、プログラマごとの品質のばらつきを抑制する
- **1.2 参照ドキュメント**: テスト観点カタログ、テスト種別カタログ、テスト仕様書フォーマット

#### シート5: 「2. 単体テスト方針」

- **2.1 単体テスト体系**: 機能テストの3分類
  - **モジュール単位**: クラス/コンポーネント対象テスト
  - **画面・バッチ単位**: 1画面/1バッチ/1エンドポイント単位テスト（例外なく実施）
  - **ユースケース単位**: 複数処理で構成される業務まとまり対象テスト
- テスト実施方法マトリクス（処理方式×機能テスト分類）
  - 自動テスト / 打鍵テスト / 対象外
- **2.2 単体テスト実施環境**
- **2.3 単体テスト終了条件**

#### シート6: 「3.1 単体テスト仕様書作成単位」

- 1つのシステム機能設計書 = 1つの単体テスト仕様書

#### シート7: 「3.3 単体テストのエビデンス」

- **(1) 画面処理方式のエビデンス**:

| エビデンス名     | 必須 | 説明                                    |
| ---------------- | ---- | --------------------------------------- |
| 単体テスト仕様書 | ○    | テストケース+実施結果                   |
| 画面ハードコピー | ○    | 画面遷移前後のキャプチャ                |
| ログ             | ○    | Webサーバログ+アプリケーションログ      |
| DBダンプ         | ○    | 対象テーブルの全データ（更新前後+差分） |
| インプットデータ | -    | DB以外のインプットデータ                |
| 処理アウトプット | -    | ファイル、メール、帳票等                |

- **(2) 画面処理方式以外**: 単体テスト仕様書のみ必須

#### シート8: 「3.4 補足事項」

- モック化の判断基準
- 業務ロジック集中型 → モック化推奨
- SQL発行主体型 → DB含めた結合テスト推奨

## テスト観点カタログ（13カテゴリ）

### 1. バリデーション

- 1-1. 単項目バリデーション（必須、文字列長、数値、文字種、コード値、日付等）
- 1-2. 相関バリデーション（条件付き必須、有効/無効の組み合わせ）
- 1-3. DBとの相関バリデーション（有効レコード存在/不在時）

### 2. DB操作

- 2-1. 共通（検索/更新/削除条件、完全一致/部分一致、エスケープ、編集仕様）
- 2-2. 検索（1件/複数件/0件、JOIN、ソート、グループ化）
- 2-3. 登録（実行結果、件数、エラー時）
- 2-4. 更新（対象あり/なし、件数、エラー時）
- 2-5. 削除（論理/物理削除、対象あり/なし）

### 3. DB制御

- 更新順序、排他制御、ロールバック、コミット

### 4. ファイル取込

- 実行結果、桁数、レコード件数、IF仕様、エラー時

### 5. ファイル出力

- 5-1〜5-7: フォーマット定義、出力内容、編集仕様、桁数、レコード件数、ソート順、画像出力

### 6. ファイル操作

- 削除、移動・リネーム、コピー

### 7. メール処理

- 送信結果、桁数、編集、エラー、ヘッダ設定、件名/本文編集、添付ファイル

### 8. 受信処理

- 実行結果、桁数、レコード件数、IF仕様、バリデーション

### 9. 送信処理

- 実行結果、エラー、電文編集

### 10. ログ出力

- ファイル操作、ログ編集、出力内容

### 11. バッチアプリケーション機能（バッチ用）

- 起動パラメータ、リラン、二重起動、コントロールブレーク、終了ステータス

### 12. ファイル取込 - バッチ固有

- 取込対象ファイル不在時

### 13. ファイル出力 - バッチ固有

- 出力先ディレクトリ不在時

## 画面処理方式で追加となるテスト観点

- **画面表示**: 初期表示、レイアウト、活性/非活性制御、表示/非表示制御
- **画面遷移**: 正常系、ブラウザバック、セッションタイムアウト
- **入力制御**: 入力文字制限、コピペ、Tab/Enterフォーカス
- **メッセージ**: 正常完了、業務エラー、システムエラー、確認ダイアログ
- **権限制御**: ロール別アクセス、ボタン/機能の権限

---

## API処理方式で追加となるテスト観点

- **リクエスト**: HTTPメソッド、ヘッダ、パス/クエリパラメータ、ボディ
- **レスポンス**: ステータスコード、ヘッダ、ボディ、エラーレスポンス
- **認証・認可**: トークン有効/無効/期限切れ、権限不足

## テストケース記載ルール

1. **該当するケース**: テスト内容に具体的な前提条件・操作手順を記載し、想定結果に期待結果を具体的に記載。対応設計書と対応箇所も必ず記載。
2. **非該当のケース**: テスト内容に非該当の理由を簡潔に記載（例：「バリデーションなし」）。
3. **テストコード列**: 自動テストの場合はテストメソッド名を記載。打鍵テストの場合は空欄。
4. **1つの観点に複数ケースが必要な場合**: 枝番を増やす（例: 59-1-1, 59-1-2）。
5. **出力項目の個別確認**: 全出力項目についてそれぞれ個別のテストケース行を作成する。
6. **各行にテスト種別（単体/結合）の列を必ず含める**。
7. **エビデンス報告書・不具合報告の参照先を明記する**。

---

## 作成手順

1. まず「単体テスト標準」を作成（プロジェクト全体のテスト方針）
2. 処理方式に応じてテスト仕様書を作成
   - バッチ → 13カテゴリの観点
   - 画面 → 13カテゴリ + 画面固有観点
   - API → 13カテゴリ + API固有観点
3. 不具合報告書フォーマットを作成
4. エビデンス報告書テンプレートを作成（全画面1ファイル）
